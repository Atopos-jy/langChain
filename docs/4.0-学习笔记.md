# LangChain.js 4.0 学习笔记：RunnableSequence 与多链编排 🏗️

> **学习时间**：2026-06  
> **核心主题**：Task Decomposition（任务拆解）— 把复杂任务拆成多个单一目标，每个子链只做一件事

---

## 一、为什么需要任务拆解？

一个复杂任务写在一个 Prompt 里，模型会**"注意力分散"**：

```
"请详细解释闭包，并总结3个要点"
  → 解释不够深入（被"总结任务"干扰）
  → 总结不够精炼（被"解释任务"污染）
```

**解决方案**：把一个复杂目标拆成多个单一目标，每个子链只做一件事。

---

## 二、核心概念

### 2.1 LCEL（LangChain Expression Language）

LangChain 表达语言，用 `.pipe()` 把 Runnable 串成流水线：

```typescript
const chain = prompt.pipe(llm).pipe(parser);
```

数据流：`input → prompt.format() → llm.invoke() → parser.parse() → output`

### 2.2 Runnable

LangChain 中所有可调用组件的统称。常见 Runnable：

| Runnable | 作用 | 输入 | 输出 |
|----------|------|------|------|
| `PromptTemplate` | 格式化模板 | `{variable}` 对象 | `string` |
| `ChatOpenAI` (llm) | 调用大模型 | messages / string | `AIMessage` |
| `StringOutputParser` | 提取文本内容 | `AIMessage` | `string` |
| `JsonOutputParser` | 解析 JSON | `AIMessage` | `object` |
| `RunnableSequence` | 多步编排 | 自定义 | 自定义 |

### 2.3 Task Decomposition（任务拆解）

核心理念：**每步只做一件事**

```typescript
// ❌ 错误：一个 Prompt 让模型做所有事
"请详细解释XX，总结3个要点，整理成JSON格式"

// ✅ 正确：拆解为三个独立子链
Step 1: 详细解释概念          → 输出 explanation
Step 2: 基于解释提炼要点      → 输出 summary
Step 3: 合并解释+要点的JSON   → 输出 结构化结果
```

## 三、两种串联方式对比

### 3.1 `pipe()` — 单值自动接力

```typescript
const chain = explainChain.pipe(summaryChain).pipe(formatChain);
// topic → explanation → summary → JSON
```

**特点**：
- ✅ 语法简洁，适合简单流水线
- ❌ **中间结果自动丢失**，后续步骤拿不到前面的数据
- ❌ 类型难以对齐（PromptTemplate 需要结构体，前一步输出的是 string）

### 3.2 `RunnableSequence.from()` — 结构化手动传参

```typescript
const chain = RunnableSequence.from([
  async (input: { topic: string }) => {
    const explanation = await explainChain.invoke({ topic: input.topic });
    return { explanation };                              // Step 1 产出
  },
  async (data: { explanation: string }) => {
    const summary = await summaryChain.invoke({ explanation: data.explanation });
    return { explanation: data.explanation, summary };   // ✅ 透传旧数据
  },
  async (data: { explanation: string; summary: string }) => {
    const json = await formatChain.invoke({
      explanation: data.explanation,   // ✅ 还能拿到 Step 1 的数据
      summary: data.summary,
    });
    return json;
  },
]);
```

**特点**：
- ✅ 每步自由控制返回值，「旧数据打包传下去」
- ✅ 可以插入任意异步函数做中间处理
- ✅ 类型安全
- ❌ 代码稍长

### 3.3 对比总结

| 特性 | `pipe` | `RunnableSequence.from` |
|------|--------|------------------------|
| 数据传递 | 单值自动传递 | 结构化手动传参 |
| 中间结果保留 | ❌ 丢失 | ✅ 可透传 |
| 中间逻辑处理 | ❌ 只能连 Runnable | ✅ 任意异步函数 |
| 类型安全 | ❌ 容易类型不匹配 | ✅ 强类型 |
| 代码复杂度 | 简单 | 稍复杂 |
| 适用场景 | 简单单向转换 | 多路数据、复杂编排 |

## 四、完整代码模板

### 基础 RunnableSequence

```typescript
import { RunnableSequence } from "@langchain/core/runnables";
import { StringOutputParser } from "@langchain/core/output_parsers";
import { PromptTemplate } from "@langchain/core/prompts";

const parser = new StringOutputParser();

// 定义各子链
const step1Prompt = PromptTemplate.fromTemplate(`...{input}...`);
const step1Chain = step1Prompt.pipe(llm).pipe(parser);

const step2Prompt = PromptTemplate.fromTemplate(`...{data}...`);
const step2Chain = step2Prompt.pipe(llm).pipe(parser);

// 组装流水线
const fullChain = RunnableSequence.from([
  async (input) => {
    const result1 = await step1Chain.invoke({ ...input });
    return { ...input, result1 };       // ✅ 透传
  },
  async (data) => {
    const result2 = await step2Chain.invoke({ data: data.result1 });
    return { ...data, result2 };        // ✅ 继续透传
  },
]);

const output = await fullChain.invoke({ ... });
```

### 核心原则

> `return` 里的东西 = 下一步的全部"口粮"
>
> 旧数据**不会自动保留**，必须手动透传

## 五、常见坑点

### ❌ 坑 1：pipe 串联时中间结果丢失

```typescript
// 用 pipe：Step 3 拿不到 Step 1 的 explanation
explainChain.pipe(summaryChain).pipe(formatChain);
// Step 3 的 formatChain 只能拿到 summary，explanation 变成了占位符
```

**解决方案**：用 `RunnableSequence.from` 手动透传

### ❌ 坑 2：PromptTemplate 的类型不匹配

```typescript
// 错误：pipe 把 string 传给 PromptTemplate（它需要 {variable} 对象）
explainChain.pipe(summaryPrompt).pipe(parser);
// TypeError: summaryPrompt expects {explanation}, not string
```

**解决方案**：用函数包装，或只用 RunnableSequence.from

### ❌ 坑 3：忘记透传旧数据

```typescript
// 错误：Step 2 只返回新数据
async (data) => {
  const result = await someChain.invoke(data);
  return result;  // ❌ 旧数据全丢了
}

// 正确：手动透传
async (data) => {
  const result = await someChain.invoke(data);
  return { ...data, result };  // ✅
}
```

## 六、在 Server 中的实战：Deep 模式

将 RunnableSequence 应用到真实的 WebSocket 后端：

### 调用链路

```
📤 用户消息
  │
  ▼
🔍 Step 1：分析问题，拆解为 2-3 个子问题
  │  输出: { question, subQuestions }
  ▼
📚 Step 2：逐一研究每个子问题
  │  输出: { question, subQuestions, research }
  ▼
✍️ Step 3：综合成最终回答
  │  输出: finalAnswer
  ▼
📦 返回给前端
```

### 核心代码

```typescript
function createDeepChain(ws: WebSocket) {
  return RunnableSequence.from([
    // Step 1：拆解子问题
    async (input) => {
      sendStatus(ws, "🔍 正在分析问题...");
      const subQuestions = await analyzePrompt.pipe(llm).pipe(parser).invoke({
        question: input.question,
      });
      return { question: input.question, subQuestions };
    },
    // Step 2：逐一研究
    async (data) => {
      sendStatus(ws, "📚 正在逐一研究子问题...");
      const research = await researchPrompt.pipe(llm).pipe(parser).invoke({
        subQuestions: data.subQuestions,
      });
      return { ...data, research };   // ✅ 透传
    },
    // Step 3：综合回答
    async (data) => {
      sendStatus(ws, "✍️ 正在综合生成最终回答...");
      const final = await synthesizePrompt.pipe(llm).pipe(parser).invoke({
        research: data.research,
      });
      return final;
    },
  ]);
}
```

### 和传统模式对比

| 模式 | 流程 | 耗时 | 回答质量 |
|------|------|------|----------|
| 传统 stream/invoke | `question → LLM → reply` | ~3-5s | 一般 |
| deep | `question → 分析 → 研究 → 综合 → reply` | ~25s | 深度、有条理 |
